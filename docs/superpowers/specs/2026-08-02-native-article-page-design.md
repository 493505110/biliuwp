# 专栏原生阅读页设计

## 背景与目标

当前活动专栏阅读页 `ArticleContentPage` 使用 WebView2 打开 Bilibili 网页。该实现依赖 WebView2 Runtime、网页结构、脚本注入和独立 Cookie 存储，且页面外观与客户端原生界面不一致。

本次改造使用专栏正文 API 获取数据，将文章信息和正文全部改为 UWP 原生控件渲染。首版保持只读，不增加点赞、投币、收藏或评论功能。

## API

使用以下接口获取专栏正文及元数据：

```text
GET https://api.bilibili.com/x/article/view?id={articleId}
```

请求通过仓库现有的 `ApiModel.Request()` 调用链发送，携带默认 `User-Agent` 和 `Referer`。接口不强制要求 WBI 签名。

成功响应的 `data` 至少使用以下字段：

- `id`、`title`、`type`、`content`
- `author.mid`、`author.name`、`author.face`
- `category`、`publish_time`
- `stats.view`、`stats.like`、`stats.favorite`
- `opus.content.paragraphs`，仅作为新版正文补缺来源

正文存在两种格式：

- `type=0`：`content` 是 HTML。
- `type=3`：`content` 是包含 `ops` 数组的 JSON 字符串，并可能同时返回更详细的 `opus`。

实测旧版文章 `cv1` 当前返回 `code=0`。接口也可能返回 `-509` 等限流或风控状态，页面必须显示 API 消息并提供重试。

## 架构

### API 层

新增 `ArticleAPI`，只负责创建 `/x/article/view` 的 GET `ApiModel`。它不解析响应，也不包含页面状态。

### 业务层

新增 `ArticleVM`，负责：

- 加载文章及暴露加载、内容、错误状态；
- 检查 HTTP 状态和 API `code`；
- 反序列化文章元数据；
- 调用正文解析器；
- 使用加载序号丢弃已过期请求结果，防止缓存页面快速切换文章时串页；
- 将异常交给现有错误处理与日志设施。

正文解析器将两种输入统一成有限的内容块集合。解析逻辑不直接创建页面控件，以保持数据解析与 UWP 展示分离。

### 内容块

首版支持以下原生内容块：

- 普通段落及行内加粗、斜体、删除线、颜色、链接；
- 一级至六级标题；
- 有序列表、无序列表和引用；
- 图片，保留原始宽高比；
- 分隔线；
- 视频、关联专栏、投票和直播嵌入卡片。

嵌入卡片显示接口提供的封面、内容类型和可用标题。点击后按现有 `MessageCenter` 导航规则处理；没有可达原生页的类型保留卡片，并提示或交给网页处理。

无法识别的正文节点记录日志并显示降级占位，不中断整篇文章。

## 解析策略

### 旧版 HTML

使用项目已有的 `HtmlAgilityPack` 解析 DOM，仅接受明确支持的标签和属性。文本先完成 HTML 实体解码；远端 HTML 不交给 `XamlReader`，也不执行脚本或样式。

支持的结构包括段落、标题、列表、引用、图片、分隔线和链接。未知标签递归保留其可显示文本；脚本、样式和不可见内容直接忽略。

### 新版 JSON

优先解析 `content.ops`：

- 字符串 `insert` 转换为文本和换行；
- `attributes` 转换为标题、列表、引用、对齐及行内样式；
- `native-image`、`cut-off`、`video-card`、`article-card`、`vote-card`、`live-card` 转换为对应内容块。

当 `content.ops` 缺失或无法解析而 `opus.content.paragraphs` 可用时，使用 `opus` 支持的文字和图片段落补缺。单个节点解析失败只影响该节点。

## 页面设计

`ArticleContentPage` 改为纯 XAML 页面，不再创建或初始化 WebView2。其他页面的 WebView2 及其 NuGet 依赖保持不变。

页面结构为：

1. 48 像素顶部栏：返回、当前标题和复制分享按钮。
2. 居中阅读列：宽屏限制正文最大宽度，窄屏使用固定页面边距。
3. 文章头部：标题、作者头像与昵称、发布时间、分区、阅读/点赞/收藏统计。
4. 正文区域：按内容块顺序原生渲染。
5. 加载层或错误层：错误层包含具体中文消息和重试按钮。

窄屏下作者信息和统计信息分行，标题字号适当减小，图片与嵌入卡片宽度跟随阅读列。字体大小不随视口连续缩放。

## 导航与分享

页面继续接受现有入口传入的数字 ID、`cv{id}` 或完整专栏 URL，并统一提取数值 ID。无效参数直接显示中文错误，不发起网络请求。

正文链接先调用 `MessageCenter.HandelUrl()`：

- 已支持的站内视频、专栏、用户、直播等内容进入原生页面；
- 普通 HTTP/HTTPS 外链经用户确认后调用系统浏览器；
- 不支持的协议显示提示，不直接启动。

分享按钮固定复制规范地址：

```text
https://www.bilibili.com/read/cv{articleId}
```

## 状态与错误处理

- 加载中：显示 `ProgressRing`，隐藏旧错误。
- 成功：一次性替换文章和正文内容，避免逐块刷新造成布局跳动。
- HTTP 失败：显示现有 HTTP 错误信息并允许重试。
- API 非零状态：显示 API `message`；`-509` 等状态不伪装成解析失败。
- 解析失败：记录详细日志，页面显示“专栏内容解析失败”并允许重试。
- 图片失败：保留图片说明或占位，不隐藏其他正文。
- 未知内容块：显示简短占位并继续渲染后续内容。

## 不在首版范围

- 点赞、投币、收藏和评论；
- 投票表单等嵌入内容的完整交互；
- 离线缓存、阅读进度和字体设置；
- 改动其他 WebView2 页面或移除 WebView2 包依赖。

## 验证

解析验证使用固定的旧版 `type=0` HTML 和新版 `type=3` JSON 样本，覆盖标题、段落、行内样式、列表、引用、图片、分隔线和嵌入卡片。

静态验证包括：

- XAML/XML 可解析；
- 新增源文件已包含在旧式 UWP 项目文件中；
- 入口参数和规范分享地址解析结果正确；
- `git diff --check` 无空白错误。

构建使用 Visual Studio MSBuild 生成主应用 `BiliBili.UWP` 的 `Debug|x64` 配置。若主应用编译成功后仅 AppX 签名或打包因本机缺少 PFX 失败，分别报告编译与打包结果，不重复构建。

运行验证至少覆盖：

- `cv1` 旧版 HTML 正文；
- 一篇新版 JSON 正文；
- 宽屏与窄屏窗口；
- 图片等比缩放与单图加载失败；
- 视频、专栏、直播等卡片跳转；
- 站内链接、外链确认和复制分享；
- API `-509`、无效 ID 和重试操作。

仓库没有 UI 自动化，Visual Studio 部署后的实际导航和视觉结果仍需人工确认；静态检查和构建不能替代运行时验证。
